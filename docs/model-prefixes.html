命名规则

四条规则，适用于表中全部前缀。

  1. 前缀固定大写、一平台一枚。OC / MS / SF / TT / ZP 与平台一一对应，同一模型列表内不与其他来源复用。
  2. 分隔符逐字节为「空格 + 间隔号 + 空格」。即 ·（U+00B7）两侧各一个半角空格，形如 OC · DeepSeek-V3.1。手填或引用模型 ID 时必须完整保留；写错分隔符（如 WB.auto、缺空格）一律不被识别。
  3. 间隔号之后保留上游模型的展示名。核心内部另用「命名空间/模型」的全限定 id 做路由，对外一律只见「前缀 · 名称」形态，两套形态不会同时出现在同一个 ID 里。
  4. 合成路由不是平台前缀。WB 只出现在 WB · auto 这一条合成入口上，见下节。

特殊 ID：WB · auto

WB WB · auto
  • 合成路由入口，不是任何平台的前缀：发布集非空时，它作为独立条目写进 WorkBuddy / CodeBuddy 的 models.json，排在逐模型条目之后。
  • 请求打到它时，核心按请求内容在当前可用模型池里自动选一个真实模型承接；池空则它根本不会出现。
  • 不计入发布模型的数量统计，也不进面板的模型列表。
  • 旧写法 WB.auto 不被任何入口接受。
