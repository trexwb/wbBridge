# WB Bridge v1.3.20 — Release 说明

> 本文件是 `v1.3.20` Release tag 的说明文档底本，可直接作为 GitHub Release 正文。

## 版本号说明

本版属既有「模型状态 / 发布」行为的定向细化（超时降权、额度受限次日重试），按 patch 递增到 **1.3.20**（`1.4.x` / `1.5.x` 段位按既定裁定不得占用）。版本 7 处落点已统一为 `1.3.20`，`npm run version:check` 通过；三份 lockfile 的版本行已手工同步（`package-lock.json` 此前滞留在 `1.3.16`，一并修正）。`status.json` 内写入的 `0.2.0` 是历史沿革值，不属版本落点。

## 主要变更

### 一、区分「超时」与「当日额度用尽」，不再一律判死

用户裁定：大量免费模型带当日限额，额度满了第二天才恢复；因此失败必须分类处置——**超时只降权，限额进入受限态、次日自动重检、通过后自动恢复**。分类本身沿用既有的 `model_status::model_result`（`category`：`quota` / `rate_limit` / `access` / `timeout` / `error`），本轮把处置接进发布链：

- **超时（`category == timeout`，探测与真实请求同口径）**：
  - 新增 `auto::TIMEOUT_PENALTY = SLOW_PENALTY = 20` 与 `auto::timeout_weight`；`next_weight` 增加 `timed_out` 参数，超时失败按档扣权重（最低 0），其余失败仍不改权重。
  - `record()`：此前已探测通过的模型超时后**不再从「已校验」集合摘除**，而是给 `modelResults[id]` 打 `soft: true` 并留在发布集（`/v1/models`、`WB · auto` 选择域、插件配置均保留）；重启后 `validated_from_results` 按 `ok || soft` 沿用这份资格。从未通过过的模型超时仍是「检测超时」、不入发布集。
  - `publishable_models` 的判定放宽为 `ok === true || soft === true`（仍在「已校验」与移除名单过滤之后）。
  - 面板状态文案：「可用 · 超时降权」（替代此前直接变「不可用」的观感），详情/tooltip 说明「仍可用，但速度权重已调低，`WB · auto` 会优先选同档更快的模型」。
- **当日额度用尽（`category == quota`）**：
  - `apply_patch` 在写 `modelResults[id]` 时补写 `restrictedUntil` = **下一个 UTC 零点**（`next_day_retry_at()`，不引入时区库）。
  - 该类失败仍摘除发布资格（状态「额度不足 · 次日重试」）。
  - 「检测全部」批量探测按 `quota_restricted` 过滤掉未到期的受限模型；整批都被跳过时服务状态给出「模型当日额度已用尽，已安排次日自动重新检测」。
  - 新增 `spawn_quota_retry` 后台任务（随 `run()` 启动，每 60 秒检查一次）：到期模型走单模型批量检测（`auto_import = true`），探测通过即按新结果整条覆盖 `modelResults`，`restrictedUntil` 随之消失、自动恢复发布；**付费白名单模型不参与自动重检**（数据红线 6）。
  - `POST /admin/set-provider-key` 成功后调用 `clear_quota_restrictions(provider)`：解除该平台所有额度受限（新 Key 可能带新额度），并落盘 `status.json`。

### 二、测试与文档

- 新增/更新单测：`auto::timeouts_lower_the_weight_instead_of_being_ignored`；`orchestration::timeouts_lower_the_weight_and_stay_publishable_when_marked_soft`、`validated_history_keeps_soft_timeouts`、`quota_failures_are_restricted_until_the_next_utc_midnight`、`quota_due_models_skip_removed_paid_and_not_yet_due_entries`。

## 已知限制

- **「次日」按 UTC 零点翻转**，不是本地零点；本机在北京时间时，额度恢复重检发生在早上 8 点左右。原因是不引入时区依赖（核心为纯 Rust、无 chrono）。
- 额度与超时的判定依赖上游错误文本 / 状态码归类（`model_status` 既有规则：`额度…不足 / 用尽`、429 等），措辞异常的上游可能被归为普通失败（摘除、不写 `restrictedUntil`）。
- 本版行为改动只在核心单测与编译层面验证；**「真实请求超时后仍发布并降权」「真实额度耗尽后次日自动恢复」两条端到端链路未在真实免费模型上实测**（免费额度不可控，无法按需复现），列入[已知限制与未验证项](../wiki/已知限制与未验证项.md)口径。
- 付费白名单模型若遭遇额度用尽，不会自动重检（红线 6），需用户手动「重新检测」。
