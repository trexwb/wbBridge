# WB Bridge v1.3.16 — Release 说明

> 本文件是 `v1.3.16` Release tag 的说明文档底本，可直接作为 GitHub Release 正文。

## 版本号说明

本版为缺陷修复（关停清空在 `BUDDY_NO_SYNC=1` 下被整段跳过），按 `1.3.x` 段位惯例递增到 **1.3.16**（`1.4.x` / `1.5.x` 段位按既定裁定不得占用）。版本 7 处落点已统一为 `1.3.16`，`npm run version:check` 通过；三份 lockfile 的版本行已手工同步。`status.json` 内写入的 `0.2.0` 是历史沿革值，不属版本落点。

## 主要变更

### 一、关闭应用必定清空三个目标的发布（含 `BUDDY_NO_SYNC=1`）

关停时清空 WorkBuddy / CodeBuddy 的 `models.json` 与 DSH 的 `wbbridge` 路由本来就在同一条 `shutdown()` 链上（`sync_published(Some(Vec::new()), true)` → `drain_sync().await`，排在运行时 SIGTERM 之前，壳的停止预算截不到它）。本轮补上唯一的豁免口子：

- `BUDDY_NO_SYNC=1` 此前会让 `sync_published` 对**任何**发布集提前返回（只写 `sync.skipped`），于是关停、启动清旧、换配置、移除最后一个模型这些**用户意图的清空**也一并被跳过——上一轮写进插件与 DSH 的条目会一直指向已停掉的端点。
- 现在该开关只拦**非空**发布；空集清空照常落盘（`skips_sync_when_disabled` 纯函数，单测钉住四种组合）。发现与探测本来就不受它控制，行为与文档一致。
- 清空范围与红线不变：`models.json` 只摘 `OWNER = 'buddy-bridge-v1'` 条目；DSH 只摘本服务 `wbbridge` 子映射（补建的空壳行整行删除），他人的 provider、注释与 `.credentials.yaml` 里其它引用原样保留；`WB_BRIDGE_API_KEY` 引用**不删**（凭据红线只增改该引用）。

### 二、测试与文档

- 新增 `dsh::tests::shutdown_clear_drops_only_our_route_and_keeps_the_credential`：经真实发布入口 `sync_all` 先发布再空集清空，钉住「路由删除 / 他人 provider 与用户注释保留 / 凭据引用保留 / 二次清理幂等」。
- 新增 `orchestration::tests::no_sync_skips_publication_but_never_the_user_intent_clear`：钉住 `BUDDY_NO_SYNC` 的生效边界。
- 文档同步：`AGENTS.md`（环境变量表、启动时序第 10 步、退出即清空三个目标）、`docs/contract.md`（关停清理链与 `NO_SYNC` 关系）、`docs/wiki/核心概念与功能.md`、`docs/wiki/使用指南.md` §7、`docs/wiki/快速开始.md` §5。

## 已知限制

- 本版只改了关停清空的**生效边界**与文档 / 单测，没有改动发布与清理算法本身；**关停清理链路（含 DSH 实盘 patch 的删除）未在真实 GUI 里逐目标复核**，证据是核心单测（`dsh.rs` 走真实临时文件）与源码链路（见[已知限制与未验证项](../wiki/已知限制与未验证项.md)）。
- 若进程被强杀（`SIGKILL` / 开发时直接 `Ctrl+C` 结束 `tauri dev` / 启动失败且核心从未装入实例），关停链不会执行，三个目标里上一轮的条目会留在原地，下次正常关停或启动清旧时才会被摘掉。
