# WB Bridge v1.3.11 — Release 说明

> 本文件是 `v1.3.11` Release tag 的说明文档底本，可直接作为 GitHub Release 正文。

## 版本号说明

本版在 `1.3.5` 之上做平台视图的交互重构、一处受控的凭据回读能力（含「打开弹窗即显示已保存的 Key」），修掉浏览器预览时的报错，在弹窗 Key 回填上补了一轮可见性修复，修掉眼睛按钮的响应与布局问题，并把眼睛的切换挪到 `pointerdown`、不再依赖 `click` 合成，按「缺陷修复 / 同范围扩展 = patch」档位落到 **1.3.11**。版本 7 处落点已统一为 `1.3.11`，`npm run version:check` 通过。`status.json` 内写入的 `0.2.0` 是历史沿革值，不属版本落点。

## 主要变更

### 一、平台列表压缩：一行一家 + 单平台配置弹窗

- 「平台」页不再每张卡片纵向堆三块内容：九家平台各占**一行**摘要（名称 / 注册表 id / 已配置或未配置 / 付费放行数），右侧一个「管理配置」按钮。
- 点按钮进入**该平台的弹窗**：官方申请指引、平台 Key 管理、付费模型白名单三块同屏。弹窗具备 `role="dialog"` + `aria-modal` + `aria-labelledby`、Tab 焦点陷阱、`Esc` 关闭，关闭后焦点归还「管理配置」。

### 二、已保存的 Key 可以查看（显式、单条）

- 新增动作 `POST /admin/reveal-provider-key`（载荷 `{ "provider": string }`，返回 `{ provider, apiKey }`）与壳命令 `core_reveal_provider_key`；动作表由 11 条增至 **12 条**。
- 只接受**注册表内且已配置**的平台，其余一律 400 `provider_not_configured`；`/admin/provider-status` 仍只回「是否已配置」，不回任何 Key 材料。
- 面板侧：**打开已配置平台的弹窗即自动回填该平台已保存的 Key**（输入框以掩码形态显示，一次一条），不必先点眼睛才能确认存了什么；点眼睛在掩码 / 明文之间切换，收起明文时**不清空**已回填的值。值只进弹窗组件内存，关闭弹窗（或保存 / 清除成功）即清出，不写 prefs / localStorage / IndexedDB / 日志。
- 已回填的值不让「原样重写」触发新一轮重检：此时保存按钮保持禁用，用户输入新 Key 后 `revealed` 标记失效、保存恢复可用；保存成功后输入框重新以掩码显示刚写入的值。
- 回填**不再依赖列表上的「已配置」徽章**：徽章来自某一次 `provider-status` 快照，核心未就绪或刷新失败时会是 false，但 `providers.json` 里其实有 Key——现在打开弹窗一律尝试取回一次。
- 回填失败不再静默：只有「尚未配置」按正常状态处理，其余失败（兜底壳命令缺失 = 应用进程还是旧版、核心未运行、浏览器预览无 IPC）在弹窗内给出可读原因，点眼睛可重试。
- 🔴 这是 `AGENTS.md` 安全红线 #7 的**第二处允许位**（第一处是用户提交 Key 的写入）。代价是：面板 WebView 内的脚本若被注入，可逐条取走所有已保存的平台 Key——该风险已如实写入已知限制。

### 三、付费白名单的模型输入改为可编辑选择器

- 输入框（`<input list>` + `<datalist>`）默认给出**当前平台最近一次发现里的已知模型**（含免费与已放行的付费），去重排序，选中即填入模型 key；不在候选里的模型仍可手动输入 `<平台 id>/<模型 id>`。
- 修正一处原有缺陷：模型 key 自身可含 `/`（如 ModelScope 的 `Qwen/Qwen3-8B`、OpenRouter 的 `meta-llama/llama-4-maverick:free`），旧逻辑按第一个 `/` 当平台前缀，会把这些正常 key 误判为跨平台输入。现在只有「首段命中别家注册表平台 id」才拒绝。
- ⚠ 候选只来自最近一次发现；**尚未放行的付费模型本来就不会被免费发现**，所以用户正要输入的那个付费 id 通常仍需手动输入，这是发现口径使然。

### 四、浏览器预览不再报 TypeError

- 现象：用 `npm run vite:dev` 打开 `http://127.0.0.1:41990`（普通浏览器预览，不是应用窗口）时点「保存」，得到 `保存失败：TypeError: Cannot read properties of undefined (reading 'invoke')`。
- 原因：`@tauri-apps/api` 的 `invoke` 直接读 `window.__TAURI_INTERNALS__`，而该全局只由 Tauri 壳注入；浏览器里没有它，于是抛出这句与业务无关的 TypeError。
- 处理：`src/core/bridge.js` 在 `action` / `readLog` / `clearLog` / `openExternal` / `aiChat` / `dataDir` / `checkUpdate` / `relaunchApp` 入口统一检测 IPC，缺失时返回可读原因「当前不在 WB Bridge 应用窗口内（浏览器里没有 Tauri IPC），无法与核心通信。请用 npm run tauri:dev 启动，或使用安装后的应用」。真实应用窗口内该全局必然存在，行为不变。

### 五、眼睛按钮即时切换、布局不再跳动

- 现象：点眼睛有时连点多次都不切换掩码 / 明文；按钮在点击瞬间缩放、图标被替换成 spinner，弹窗高度随之跳动。
- 原因：显示 / 掩码被写成「等取回结果再改状态」——`revealing` 只由 `revealSavedKey` 的回包写入，取回在飞期间点击会被早退吞掉；按钮又被 `revealingBusy` 与全局 `busy` 禁用（壳侧请求超时上限 60s，核心慢时按钮长时间不可用）。同时按钮内 spinner / 图标互换、失败行随点击出现与消失，改变了弹窗高度。
- 处理：显示 / 掩码改为**纯本地同步切换**，点击立即生效、不再等待核心；取回只在「切到显示且草稿为空」时后台触发，值回来后按当前模式呈现（明文直接可见，掩码则留在框内），不反写 `revealing`。按钮不再被在飞状态禁用（仅保存中禁用），图标不再被 spinner 替换、宽高固定。取回中的提示只走输入框占位文案「正在读取已保存的 Key…」，不插入额外行，弹窗高度不变。

### 六、眼睛在 pointerdown 上切换，不再依赖 click 合成

- 现象：平台弹窗**刚打开**的那一下点眼睛，图标与输入框的掩码 / 明文都要等几秒才有反应，之后才恢复正常。
- 原因：上一轮已把切换做成纯本地状态，但入口仍绑在 `click` 上。`click` 需要 press 与 release 落在同一个元素上才会派发——弹窗入场动画 `enter-rise`（4px / 260ms）还在推动整块面板时，按下与松开之间按钮会挪位，浏览器于是把 `click` 派发给共同祖先、甚至不派发；`.mask` 的 `@click.self` 也可能抢到这次点击。表现就是「刚打开时点了没反应，等动画/状态稳定后再点才行」。另外开发窗口里组件被 HMR 打过补丁时，已挂载实例的 setup 闭包仍是旧的（切换仍要等取回），只有重载窗口才会换上新实现。
- 处理：眼睛改绑 `@pointerdown`（`button === 0`），按下即切换，不再等 `click` 合成；键盘 / 辅助技术没有 pointerdown，仍走 `@click`，两者用 700ms 时间戳互斥，一次操作只翻一下。输入框 `type`、图标、`aria-pressed` 全部由同一次状态写入驱动，尺寸与位置不变。
- 🔴 该改动只影响切换事件的入口，不碰取回链路：Key 依旧只在用户显式操作时经 `reveal-provider-key` 取回，值只留在弹窗组件内存。

## 已知限制（本版相关）

- Key 回读是「可被面板脚本调用」的：依赖面板代码本身可信，不提供二次口令或系统钥匙串保护。
- 白名单候选来自最近一次发现，不含「尚未放行、因此尚未发现」的付费模型。
- 放行 = 真实计费；探测与对话都按平台标价扣费。当前核心的 `WB · auto` 选择域仍按免费池过滤（`auto::free_pool` 排除 `paid: true`），辅助转写与自愈重检同理。
- Windows / Linux 实机、自动更新客户端升级闭环、商业签名 / 公证等既有未验证项不变。

完整边界见 [`docs/wiki/已知限制与未验证项.md`](../wiki/已知限制与未验证项.md)。
