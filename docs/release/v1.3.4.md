# WB Bridge v1.3.4 — Release 说明

> 本文件是 `v1.3.4` Release tag 的说明文档底本，可直接作为 GitHub Release 正文。

## 版本号说明

`v1.2.5` 是上一个已打标签并发布的版本。此后 `1.3.0`–`1.3.4` 只在内部推进，均未构建、未打标签；本轮的全部代码改动集中在一个开发提交里，文档随后同步到 `1.3.4`。本版把这整段时间的改动一次性发布：

- **`WB · auto` 速度权重路由**：探测耗时定权、慢请求扣权、全池归零后自动重检、同档择优；
- **手动移除模型 + 模型回收站**：长期不可用的模型不再检测、不再发布，可从回收站恢复；
- **五家新平台**：爱思 Agnes / 商汤 SenseNova / NVIDIA NIM / OpenRouter / Hugging Face，注册表扩到九家；
- **AI 助手感知移除模型**：快照与工具统计按活跃模型计算，并单独报出移除数量；
- **壳侧停止兜底**：HTTP 不可用时改走进程内关停，仍执行同一条插件配置清理链；
- 文档同步与前端依赖升级。

版本落点共 7 处（根 `package.json`、`src-tauri/tauri.conf.json`、壳 `Cargo.toml`、核心 `Cargo.toml`、`AGENTS.md` 基准表三行），已统一为 `1.3.4`，`npm run version:check` 通过。两份 `Cargo.lock`（壳与核心各自独立 workspace）内的本地包版本已随 cargo 同步为 `1.3.4`。`status.json` 内写入的 `0.2.0` 是历史沿革值，不属版本落点。

## 主要变更

### 一、`WB · auto` 改为按速度权重路由

此前 `WB · auto` 只在能力档位（是否支持图片 / 工具）相同的候选里随机选一个；模型快慢完全不影响选择。本版让「快」成为同档内的首选依据：

- **探测成功时按耗时定权**（`auto::probe_weight`）：≤2s → 100、≤5s → 80、≤10s → 60、≤20s → 40、≤40s → 20，更慢 → 10。权重恒为正，避免刚探测完就凑满「全池归零」。
- **真实请求成功且整条耗时 ≥30s 扣 20**（`SLOW_REQUEST_MS = 30_000`、`SLOW_PENALTY = 20`）：快请求不涨权，失败不改权（失败模型本身已按既有判决被移出可用集合）。
- **选择器只比同档候选**：先按图片 / 工具能力筛出候选层，候选为空才退回全池；同档内取权重最高者，同权重时用既有 `protocol::random_uuid()` 取模随机分散——**没有引入随机数依赖**。
- **全池归零自愈**：所有可用模型权重都为 0、且当前没有读取 / 探测在进行时，**下一次真实请求**触发一次全量重新检测，探测通过即按新耗时重新分配权重。探测路径本身不触发（否则全失败的一轮会反复自检）。
- **持久化**：权重写在 `status.json` 的 `modelResults.<全限定 id>.weight`，属加法式字段，`schemaVersion` 仍为 `1`；旧版 `status.json` 缺 `weight` 时按满分 100 处理，不会把旧数据误判成「权重耗尽」。
- **面板**：模型行新增「权重 N」徽章；同一状态档内改为按权重从高到低排序（权重相同再按名称），列表顺序与 `WB · auto` 的挑选偏好一致。

新增核心单测覆盖定权分档、慢请求扣权边界、探测重新定权、耗尽判定、同档择优、同权重只在高权重集合内分散、权重不跨能力档等。

### 二、手动移除模型 + 模型回收站

长期「不可用 / 访问受限」的模型此前只能反复出现在探测队列里。本版提供显式移除与恢复：

- **移除入口只出现在明确不可用的行**（`canRemove` 要求 `unavailable`），不是整理可用模型的捷径。两段式确认：第一次点击变成「确认移除」，3 秒未确认自动退回；400ms 内的第二次点击被忽略，防顺手双击。
- **移除 = 不再检测、不再发布**，不是删除目录条目。移除名单按**全限定 id** 持久化在 `settings.json` 的 `removedModels`（排序去重、非法值丢弃），并写入 `status.json` 顶层 `removedModels` 供面板分组；跨重启生效。
- **四处排除**：探测队列、`publishable_models`、`/v1/models` 与插件 `models.json`、`WB · auto` 选择域；AI 助手的活跃统计同样排除。刷新与自动重检都不会把它拉回。
- **允许显式移除造成空发布集**：把最后一个模型移除后，插件配置必须真的清空；空集闸门默认「保留既有配置」是为了防发现失败误清，不适用于这条用户显式意图。
- **恢复后立即单检一次**：恢复只解除过滤，不等于宣布可用；探测通过才重新进入发布集，失败则回到不可用状态但已不在移除名单。重复恢复幂等（`restored: false`）；模型不在当前目录时返回 400 `model_not_found`。
- **回收站是页内子面板，不是侧栏菜单项**：工具条按钮在列表态显示「回收站（N）」，进入后变成「模型列表」，再点一次或按 `Esc` 返回。已移除模型只在回收站里展示与恢复，**绝不与参与检测的模型同屏混排**；详情若正选中被移除的模型会立即收起。
- **列表布局修复**：模型列表改为「外层 `.models` 滚动 + 内层 `.list` 用 `flex: 1 0 auto` 按内容撑开」，内容高于容器时交给外层滚动，不再被压进固定高度后溢出到页脚上；空列表且存在已移除模型时，空态文案直接指向上方的「回收站」。

契约侧新增两条 `POST /admin/*` 与两个壳命令，动作表由 8 条增至 **10 条**：

| 动作 | 路由 | 载荷 | 说明 |
|---|---|---|---|
| `remove-model` | `/admin/remove-model` | `{ model }` | 加入移除名单，同步摘除通过集并立即收敛插件配置 |
| `restore-model` | `/admin/restore-model` | `{ model }` | 移出移除名单并立即发起一次单模型探测 |

壳侧对应 `core_remove_model` / `core_restore_model`；`bridge.js` 完成映射；`ops.js` 为两个动作补了成功文案（明确告知「可在顶部回收站恢复」）。`shell_action_routes_match_the_core_contract` 继续逐项对齐两侧动作表。

### 三、新增五家平台，注册表扩到九家

平台注册表新增：

| 平台 | id | 短前缀 | OpenAI 兼容端点 |
|---|---|---|---|
| 爱思 Agnes | `agnes` | `AG` | `https://apihub.agnes-ai.com/v1` |
| 商汤 SenseNova | `sensenova` | `SN` | `https://token.sensenova.cn/v1` |
| NVIDIA NIM | `nvidia` | `NV` | `https://integrate.api.nvidia.com/v1` |
| OpenRouter | `openrouter` | `OR` | `https://openrouter.ai/api/v1` |
| Hugging Face | `huggingface` | `HF` | `https://router.huggingface.co/v1` |

- 五家都**不带权威模型清单**：目录与免费判定沿用 models.dev catalog，注入段只做鉴权锚点，行为与既有「其余三家」一致。
- 面板「平台」视图新增五张卡片与各自的分步申请指引，官方申请页经壳 `open_external` 打开（https + 主机名白名单）。
- AI 助手的平台白名单、`PROVIDER_PAGES` 与平台状态工具同步扩到九家；`red_lines.rs` 的平台集合断言同步更新，新增平台必须一并改该断言。
- 客户端展示 ID 的短前缀表补入 `AG` / `SN` / `NV` / `OR` / `HF`，`docs/model-prefixes.html` 同步。

⚠ 五家只按 models.dev 目录 id 与端点接线，**没有一家用真实 Key 跑过「发现 → 探测 → 发布」**。

### 四、AI 助手感知已移除模型

`ai.js` 新增 `activeModelsOf(state)`：状态快照、`list_models` 与 `get_status` 一律按「目录 − 移除名单」计算模型数与模型行，并在快照里单独报出「另有 N 个已被用户移除（不检测、不发布，可恢复）」。助手因此不会把已移除模型算进可用统计，也不会在 `list_models` 里推荐它们。`npm run test:ai` 由 18 项增至 **19 项**。

### 五、壳侧停止兜底：HTTP 不可用时仍走同一条清理链

`stop_core` 原先只走 `POST /admin/shutdown`：拿不到 API Key，或核心还在 `find_runtime` / 下载运行时、回环服务尚未监听时，只能直接关闭运行时，**连带丢掉关停清理**，WorkBuddy / CodeBuddy 里本工具名下的条目就留在配置里了。

本版在 HTTP 路径失败后增加一道进程内兜底：核心与壳同进程，直接调用 `orchestration::request_shutdown(core.runtime.handle(), 0)`，让核心走**与 `/admin/shutdown` 完全相同**的 `shutdown` 清理链（含插件条目清空与串行写链落盘），等待有界窗口后再关闭运行时；只有这条也走不通才强制关闭。退出预算保持短：HTTP 5s + 等待 10s，进程内等待 5s。

⚠ 该兜底分支只有代码级证据，**没有在「启动中退出」的真实时序下实测过**。

### 六、文档、依赖与工程

## 安装与升级

- **全新安装**：下载对应平台的安装包（macOS `.dmg` / Windows `-setup.exe` / Linux `.AppImage` 或 `.deb`）。
- **应用内更新**：`v1.0.2` 起支持；`v1.0.1` 及更早版本没有 `.sig` / `latest.json`，需手动下载安装包升级一次。
- **更新通道**：Draft Release 发布后由维护者点 Publish 才对客户端可见（灰度闸门）；`latest.json` 由 CI 的 `update-manifest` 作业唯一写入。
- ⚠ **发布前提**：`v1.3.4` 尚未构建、未打标签；只有走完「推进版本提交 → 在该提交上打 `v1.3.4` 标签 → 推标签」的既定流程，才会产出六平台产物与更新清单。

### macOS 首次打开

应用使用 ad-hoc 签名（未做 Apple 公证）。首次打开若被拦截：先尝试打开，再到「系统设置 → 隐私与安全性」点击「仍要打开」；若提示「已损坏」，确认来源可信后执行：

```sh
xattr -dr com.apple.quarantine "/Applications/WB Bridge.app"
```

## 已知限制（本版相关）

- **速度权重不是成功率**：失败不扣权（失败模型直接被摘出发布集）、快请求不涨权；全池归零只在真实请求路径触发一次重检；权重只影响 `WB · auto` 的同档择优与面板排序，不改变 `/v1/models` 的发布集。
- **移除只影响本工具**：不删除上游目录条目，也不会阻止模型在别的客户端里使用；恢复后必须探测通过才重新进入发布集。
- **移除入口只对不可用模型开放**：可用模型的行内没有「移除」，避免把日常整理误当成故障处置。
- 五家新平台只按目录与端点接线，**未用真实 Key 验证**；免费清单与可用性仍由各平台与 models.dev 决定。
- 权重与移除 / 回收站目前只有核心单测与浏览器内面板验证，**未在真实 Tauri GUI 走完整链路**；壳侧停止兜底未在启动中退出时实测。
- Windows / Linux 包仍由 CI 构建，尚未在真实机器上安装与冷启动。
- 自动更新「检查 → 下载 → 安装 → 重启带新版本起来」的客户端闭环尚未端到端走过。
- 未做商用代码签名 / 公证：Windows 可能提示未知发布者，macOS 需按上方步骤放行。

完整边界见 [`docs/wiki/已知限制与未验证项.md`](../wiki/已知限制与未验证项.md)。
