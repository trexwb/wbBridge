## 测试与验收

- 核心测试全部用 Rust：`cargo test`（`src-tauri/core/`），三层——lib 单元测试（`src/*.rs` 内 `#[cfg(test)]`）、`tests/js_parity.rs`（JS↔Rust 对拍，比较 `tests/fixtures/*.json` 里冻结的 `expected`）、`tests/red_lines.rs`（运行期红线守卫）。**验收判据：三层全绿，且 `git diff --stat src-tauri/core/tests/fixtures` 为空（禁止改夹具让测试通过）。**
- 壳（`src-tauri/`）另有 `cargo test --lib`：日志尾部读取、`shell_action_routes_match_the_core_contract`（壳 `ADMIN_ROUTES` ↔ 核心 `ACTION_ROUTES` 逐项一致）、退出链路 3 项、`status_read_needed_only_skips_when_mtime_is_known`（`status.json` 轮询的 `(mtime, 长度)` 前置过滤：拿不到 mtime 时不得跳过读内容）。
- **JS 侧四个套件**都用 `node --test`（不引测试框架、不依赖 DOM）；CI 的 test 作业里对应「运行面板偏好、操作守卫、更新清单与签名注入单测」一步。改对应实现**必须同步改测试**：
  - `npm run test:prefs` → `src/core/prefs.js`：键白名单 / 值字段投影 / 坏数据回落 / 存储不可用降级 / 超大值拒写 / 12h 静默检查节流。改白名单或投影必须同步改测试。
  - `npm run test:ops` → `src/core/ops.js`（操作守卫唯一实现）：常量合法性、终态动作集合与文案表、**在飞互斥**（连点不闪烁反馈条）、**完成冷却**（终态动作成功后 5 秒内重复触发被拒，失败不进冷却）、**拒绝节流**与时钟回拨、成功反馈文案的存在性（import 与平台 Key 动作不被代写）。改守卫阈值或文案必须同步改测试。
  - `npm run test:manifest` → `scripts/gen-latest-json.mjs`（`latest.json` 唯一写者）：六平台成功路径与各类必须失败的路径，用 `spawnSync` 跑**真脚本** + 临时产物目录，不联网、不碰真实产物。成功路径的 url 断言是**点形式**（`WB.Bridge_…`）——GitHub 上传时把 Release 资产名里的空格规范化成 `.`，脚本因此先 `name.replace(/ /g, '.')` 再编码；按本地文件名拼出的 `%20` 形式一律 404。改平台识别或失败判定必须同步改测试。
  - `npm run test:updater-key` → `scripts/with-updater-key.mjs`（签名注入包装器）：取值优先级（显式空口令压过文件口令、`~/` 先展开）、内联位两种形态的判定与 trim、注入后删除互斥的 `_PATH`、明文钥置空口令 / 加密钥缺口令只告警、公钥配对只认配置第一条且只告警、`buildCommand` 三种入参、CLI 相对路径调用确实执行且不回显密钥，外加接线断言（`tauri:build` 经本包装器、`build` 链 `make:dmg`、`release.yml` 读 `vars.` 且调用 `npm run tauri:build`、`plugins.updater.pubkey` 恰好一条、`bundle.targets` 不含 dmg）。只用合成假 base64 串与临时目录，**不联网、不调 tauri CLI、不读 `~/.tauri`、不碰真实私钥**。改取值 / 归一 / 口令 / 配对判定必须同步改测试。
- **JS↔Rust 对拍已快照化**：`tests/fixtures/*.json` 每个用例带 `expected` 黄金快照（迁移前由 JS 实现录制，已抹平随机 id / `created` / `ms` / sync 文案；沙箱绝对路径在比较前还原成 `$BASE` 占位符，快照不绑定机器与目录布局）。**默认不启动 Node**，但要求与归档的 JS 实现逐字段一致。
  - 需要重新录制：把仓库外归档 `backup/wbBridge-node-20261001/` 的 `core/` 与 `core-rs-tests-js/`（归档内目录名，放回后即 `tests/js/`）放回原位，再执行 `WB_PARITY_RECORD=1 cargo test --test js_parity`。
  - **禁止**在没有 JS 真相的情况下手工编辑 `expected` 来"让测试通过"——这会同时毁掉测试的证据价值。
- **测试严禁真实联网、真实下载**：网络与运行时行为必须通过既有注入点替换（`RuntimeOptions` 的 `FetchFn` / `LatestFn` / `ProbeFn`、`SyncIo`、`atomic::replace_with_retry_with`）。
- 新增 / 修改行为必须补测试；触碰安全、供应链、数据红线时，优先在 `tests/red_lines.rs` 补断言而不是只写文档。
- 修改 `src-tauri/core/src/` 后必须运行 `cargo test` 并报告**实际**通过 / 失败数量，**不得以"应该能过"代替执行**；`cargo clippy --all-targets` 必须保持 **0 warning**。
- `cargo fmt --check` 全仓并不干净（**未作为门禁**），代码风格以 clippy 0 warning 为准；勿在无关文件上顺手格式化。

## 编码规范要点

### Rust 核心

- `src-tauri/core/` 是**纯 Rust、无 Node 依赖**；edition 2021。
- 跨语言语义对齐靠 `json.rs` 的 JS 等价原语（`truthy`、`strict_eq`、`js_stringify`、`Env`）与 `serde_json` 的 `preserve_order`；**不得改用无序 map**（键序是 `models.json` 合并语义的一部分）。
- 新增运行期依赖必须说明理由；禁止把任何 Node 运行时、pkg、esbuild 重新引入核心链路。
- 异步一律 `async/await` + tokio；共享可变状态用 `Arc<Mutex<..>>` / 原子量，串行写链（`Slot` + `CHAIN_SEQ`）不得改成并发写。
- 业务错误统一 `BridgeError { message, status, code }`（`protocol.rs`），不得吞掉错误或返回无码错误。
- 注释写**为什么**，不写"是什么"；平台差异集中在 `platform.rs` / `system_proxy.rs` / `runtime.rs`，业务代码不得散落平台判断。
- 日志只写非敏感信息；**严禁**把 `api-key`、`OPENCODE_SERVER_PASSWORD`、用户凭据写入日志或 `status.json`。
- 文件写入优先走 `atomic.rs::replace_with_retry` 或 `sync.rs::atomic_write`，禁止裸 `rename` 覆盖；新建目录 / 敏感文件显式权限（目录 `0700`、密钥文件 `0600`）。
- **`WB · auto` 合成路由条目只在生产发布链写入插件配置**：`sync.rs` 的 `merge_models_auto` 走 `SyncOptions.auto_route`，该字段**默认 `false`**——JS 侧从来没有这一条，`tests/js_parity.rs::sync_options` 显式钉 `false`，因此对拍路径逐字节不变（改这里若把默认值翻成 `true`，`tests/fixtures/sync.json` 立刻失败，那是**预期的护栏生效**，不是要修的测试）。条目 `id` 刻意**绕过** `client_model_id`（否则变成 `OC · WB · auto`，与 `server.rs::chat()` 的字面比较永不匹配 ⇒ 改写不生效）。`sync.rs::owned_count` **必须排除别名**，否则 `sync.count` / `status.json` 的 `sync.targets.<目标>.count` 不再是「发布的模型数」。别名只进插件文档的 `availableModels`，**不进** `status.json` 的模型列表，面板因此没有也别新增这一行。`supportsToolCall` 必须取自 `auto::any_tool_capable(models)`（与 `auto.rs` 私有的档位谓词同源），不得写成固定 `true`——否则插件侧声明与核心选档可能分叉。
- **插件配置写入不再产生任何备份**：`sync.rs` 的写路径没有备份区块，现存的是 `sweep_old_backups(file)`——在**两条出口**都调用（`atomic_write_with` 成功之后，以及内容无变化的早退之前），按**逐段白名单**（文件名以 `<配置文件名>.buddy-bridge-` 开头、以 `.bak` 结尾、中段全是 ASCII 数字、必须是普通文件；跳过目录、`read_dir` 失败静默）只清理本工具**旧版**攒下的存量备份。不得新增备份逻辑，也不得把判定放宽成通配删除（用户自己命名的 `*.bak`、`*.tmp` 一律不碰）。写盘保护只剩三道：文件锁 + 写前二次读取 + 原子替换（同目录临时文件再 `rename`）。

### UI 规范

- 面板 = Vue 3 SFC + Vite 构建产物 `dist/`，由 Tauri WebView 加载；**不得引入 CDN 或任何外部请求**，必须满足 `tauri.conf.json` 的 CSP（`default-src 'self'`、`script-src 'self'`、`connect-src ipc: http://ipc.localhost`）。
- 与壳的通信只走既有契约 `src/core/bridge.js`；**不得新增或改名 IPC 命令 / 事件**，除非同步更新 `src-tauri/src/lib.rs` 与 `capabilities/default.json`。
- 面板为只读展示 + 动作触发：不得在面板内直接读写文件、访问网络、调用 OpenCode；动作执行期间必须置忙（按钮禁用 + spinner + 结果反馈），失败必须显示原因。
- 详情面板是**右侧常驻分栏**，无遮罩、不 `position: fixed/absolute`、不覆盖列表；**任何窗口宽度都不降级为上下堆叠**（`src/` 内现存的媒体查询只有 `prefers-color-scheme` 与 `prefers-reduced-motion` 两处）。收起详情三条等价路径：`Esc`、详情头部「收起详情」按钮、窗口失焦。
- 侧栏为分组导航（模型 / 运行 / 集成 / 其他 + 底部「运行设置」），**6 个入口都是已实现视图**（模型与服务 / **平台** / 运行日志 / 用量与额度 / 插件集成 / 关于与更新，对应 `src/core/prefs.js` 的 `VIEW_IDS = ['models','providers','logs','usage','workbuddy','about']`），视图由 `src/App.vue` 的 `view` 持有、按当前视图高亮并带 `aria-current="page"`；**禁止**再出现「规划中」标签、禁用占位或可点击却无响应的假入口。
- 新增视图必须遵守只读边界：`read_log` 只读日志尾部、`usage` 只读快照字段、集成视图唯一动作是复用既有 `import`；不得在视图内新增写文件或联网行为。**唯一例外是「平台」视图**——它是面板里唯一写凭据的入口（提交/清除平台 Key 经既有 `set-provider-key` / `clear-provider-key` 管理动作，落盘只有数据目录 `providers.json`，`0600`），视图自身不落文件、不回显 Key。
- 尺寸与颜色一律取自 `src/styles/variables.css`（小字号说明文字用 `--muted-strong`，普通次要文字用 `--muted`），不得在组件里写死颜色或宽度。

| 布局常量 | 值 | 位置 |
|---|---|---|
| 默认窗口 | `1120 × 720` | `src-tauri/tauri.conf.json` → `app.windows[0]` |
| 最小窗口 | `860 × 560`（`minWidth` / `minHeight`） | 同上 |
| 侧栏宽 | `--sidebar-w: 208px` | `src/styles/variables.css` |
| 详情栏宽 | `--details-w: clamp(300px, 45%, 360px)` | 同上 |
| 宽度断点 | **无**（不按窗口宽度堆叠） | `src/` 内无宽度媒体查询 |

## Git 提交规范

提交格式：`type(scope): content`

| type | 说明 | | scope | 范围 |
|---|---|---|---|---|
| `feat` | 新功能 | | `core` | `src-tauri/core/` |
| `fix` | 修复 | | `ui` | `src/` 面板与 Vite |
| `docs` | 文档 | | `tauri` | 壳与 `src-tauri/icons/` |
| `style` | 格式调整（不影响逻辑） | | `scripts` | 版本脚本 |
| `refactor` | 重构 | | `docs` | 文档 |
| `perf` | 性能优化 | | `ci` | 工作流 |
| `test` | 测试 | | | |
| `chore` | 构建 / 工具 / 依赖 | | | |

示例：`refactor(core): 移除 Node sidecar，核心改为 Rust 内嵌`

提交纪律：

- 提交前必须运行 `cargo test`（`src-tauri/core/`）；测试失败禁止提交。
- 一次提交只包含一类改动，禁止把源码改动与大批二进制 / 图标混在一起。
- **严禁提交**：`api-key`、`.env.local`、`status.json`、`settings.json`、`node_modules/`、`dist/`、`src-tauri/target/`、`src-tauri/core/target/`、`src-tauri/gen/`、`.zwork/`、任何私钥文件，以及仓库外的 Node 归档目录。
- 仓库现状：分支 `dev`，远端 `origin = https://github.com/trexwb/wbBridge.git`（另有 `main`）。提交前务必 `git status` 复核实际纳入内容。
- Agent 完成改动后**不得自动执行** `git commit` / `git push`，除非用户在本轮明确要求。

## 变更与交付约定

1. **改动前**：读取目标文件原文；涉及 `orchestration.rs` 编排、`server.rs` 路由、`protocol.rs` 校验、`runtime.rs` 下载的逻辑，必须同时阅读相关测试（含 `tests/fixtures/*.json` 的快照断言）确认既有行为边界。
2. **改动中**：一次只改一个独立区块 / 函数，避免大范围替换；不修改与任务无关的文件。
3. **改动后**：运行 `cargo test` 与 `cargo clippy --all-targets` 并给出**真实的**通过 / 失败与 warning 数量；用 `grep` / `read` 验证改动已落盘；若改动涉及对外契约（路由、错误码、`status.json` 字段、`models.json` 写入格式、IPC 命令 / 事件），必须在回复中显式列出影响面；若触及红线，同步更新 `tests/red_lines.rs`。
4. **遇到不确定**：宁可询问，也不要凭推测修改安全、供应链、隔离相关代码。
5. **文档类改动不推进版本号**（见[版本与发布](版本与发布)）。
